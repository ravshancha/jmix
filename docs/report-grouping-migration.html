Hisobotlarni guruhlash: boshqa tizimga ko'chirish

«Отчеты» sahifasi (Jmix 2.8, ReportingMainView) uchun pagination oldidagi «Все / По группам / По доменам» tanlovi

Nima qilinadi

  • Toolbar o'ng tomonida, pagination oldidan select qo'shiladi: Все, По группам, По доменам. Standart qiymat — «По группам»: sahifa ochilganda ro'yxat darhol guruhlar bo'yicha daraxt bo'lib chiqadi.
  • «Группа» yoki «Домен» filtridan bittasi tanlansa ham, pagination oldidagi select avtomatik «Все»ga o‘tadi va butunlay bloklanadi. Ikkala filtr ham tozalanganda select yana ochiladi; qiymat «Все» bo‘lib qoladi.
  • Все tanlansa oddiy (tekis) jadval, avvalgidek ustun bo'yicha saralash va filtrlar bilan ishlaydi.
  • По группам yoki По доменам tanlansa, so'rov avval guruh/domen nomi, keyin hisobot nomi bo'yicha saralanadi. Sahifa ochiladigan sarlavhali daraxt ko'rinishida chiqadi, masalan «Тестирование (2)». Guruhi yo'q hisobotlar oxirida «Без группы» / «Без домена» ostida turadi.
  • Pagination o'zgarmaydi: har sahifada 20 ta hisobot. Saralash bazada bo'lgani uchun bir guruh sahifalar orasida aralashib ketmaydi.
  • Daraxtda tanlangan qator oddiy jadvalga ham tanlanadi. Shuning uchun «Выполнить», «Описание», «История исполнения», «Доступы» va kontekst menyu hech o'zgarishsiz ishlaydi.

package uz.kapitalbank.umida.entity;

import io.jmix.core.metamodel.annotation.InstanceName;
import io.jmix.core.metamodel.annotation.JmixEntity;
import jakarta.persistence.Id;
import org.springframework.lang.Nullable;

/**
 * Строка сгруппированного списка «Отчётности»: либо заголовок группы (группа отчётов или домен),
 * либо отчёт внутри неё. Не сохраняется — собирается в памяти из загруженной страницы
 * {@link UserReport}, чтобы дерево показывало отчёты под раскрывающимися заголовками.
 */
@JmixEntity(name = "umida_ReportListRow")
public class ReportListRow {

    @Id
    private String id;

    /**
     * Название группы у заголовка или название отчёта у строки отчёта.
     */
    @InstanceName
    private String name;

    /**
     * Заголовок группы, под которым лежит отчёт; у заголовка пусто — по нему дерево раскладывает
     * уровни.
     */
    private ReportListRow parent;

    /**
     * Строка «Отчётности», которую представляет строка дерева; у заголовка группы пусто.
     */
    private UserReport userReport;

    private String code;

    private String owner;

    private String reportGroup;

    private String domain;

    public String getId() {
        return id;
    }

    public void setId(String id) {
        this.id = id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    @Nullable
    public ReportListRow getParent() {
        return parent;
    }

    public void setParent(@Nullable ReportListRow parent) {
        this.parent = parent;
    }

    @Nullable
    public UserReport getUserReport() {
        return userReport;
    }

    public void setUserReport(@Nullable UserReport userReport) {
        this.userReport = userReport;
    }

    public String getCode() {
        return code;
    }

    public void setCode(String code) {
        this.code = code;
    }

    public String getOwner() {
        return owner;
    }

    public void setOwner(String owner) {
        this.owner = owner;
    }

    public String getReportGroup() {
        return reportGroup;
    }

    public void setReportGroup(String reportGroup) {
        this.reportGroup = reportGroup;
    }

    public String getDomain() {
        return domain;
    }

    public void setDomain(String domain) {
        this.domain = domain;
    }
}

3.5 Guruhlash logikasi

MetadataTools, DataManager va MessageBundle view'da allaqachon inject qilingan bo'lishi kerak.

    /**
     * Выбор строки дерева переносится в плоский грид: все команды тулбара и контекстного меню —
     * его действия и берут отчёт из его выделения. Заголовок группы выделение снимает.
     */
    private void initGrouping() {
        groupingField.setItems(ReportGrouping.values());
        groupingField.setItemLabelGenerator(item -> messageBundle.getMessage(item.messageKey));
        groupingField.setEmptySelectionAllowed(false);
        // По умолчанию список сгруппирован по группам отчётов; «Все» — плоский список.
        groupingField.setValue(ReportGrouping.BY_GROUP);
        refreshGroupingEnabled();
        applyGroupingMode();
        groupingField.addValueChangeListener(e -> {
            refreshGroupingEnabled();
            applyGroupingMode();
            reloadReports();
        });

        groupedReportsDataGrid.setPartNameGenerator(row ->
                row.getUserReport() == null ? GROUP_HEADER_PART : null);
        groupedReportsDataGrid.addSelectionListener(e -> {
            ReportListRow row = groupedReportsDataGrid.getSingleSelectedItem();
            if (row != null && row.getUserReport() != null) {
                userReportsDataGrid.select(row.getUserReport());
            } else {
                userReportsDataGrid.deselectAll();
            }
        });
    }

    /**
     * При фильтрации по группе или домену доступен только плоский список «Все».
     * Выбор группировки снова доступен после очистки обоих фильтров.
     */
    private void refreshGroupingEnabled() {
        groupingField.setEnabled(!hasGroupingFilter());
    }

    private boolean hasGroupingFilter() {
        return !groupFilterField.isEmpty() || !domainFilterField.isEmpty();
    }

    private void onGroupingFilterChanged() {
        if (hasGroupingFilter() && groupingField.getValue() != ReportGrouping.NONE) {
            // Listener режима сам обновит доступность select и перезагрузит список.
            groupingField.setValue(ReportGrouping.NONE);
        } else {
            refreshGroupingEnabled();
            reloadReports();
        }
    }

    private void applyGroupingMode() {
        boolean grouped = isGrouped();
        userReportsDataGrid.deselectAll();
        groupedReportsDataGrid.deselectAll();
        userReportsDataGrid.setVisible(!grouped);
        groupedReportsDataGrid.setVisible(grouped);
    }

    private boolean isGrouped() {
        ReportGrouping grouping = groupingField.getValue();
        return grouping != null && grouping != ReportGrouping.NONE;
    }

    /**
     * Перестраивает дерево после каждой загрузки страницы. Запрос уже отсортирован по группе,
     * поэтому заголовки идут в том же порядке, а отчёты внутри группы сохраняют порядок запроса.
     */
    @Subscribe(id = "userReportsDc", target = Target.DATA_CONTAINER)
    public void onUserReportsDcCollectionChange(CollectionContainer.CollectionChangeEvent<UserReport> event) {
        if (event.getChangeType() == CollectionChangeType.REFRESH) {
            rebuildGroupedRows();
        }
    }

    private void rebuildGroupedRows() {
        if (!isGrouped()) {
            groupedRowsDc.setItems(List.of());
            return;
        }
        ReportGrouping grouping = groupingField.getValue();

        Map<String, ReportListRow> headers = new LinkedHashMap<>();
        Map<ReportListRow, Integer> counts = new HashMap<>();
        List<ReportListRow> reportRows = new ArrayList<>();
        for (UserReport userReport : userReportsDc.getItems()) {
            Object groupKey = grouping == ReportGrouping.BY_GROUP
                    ? userReport.getReport().getGroup()
                    : userReport.getDomain();
            String headerId = groupKey == null ? "none" : String.valueOf(EntityValues.getId(groupKey));
            ReportListRow header = headers.computeIfAbsent(headerId, id -> {
                ReportListRow row = dataManager.create(ReportListRow.class);
                row.setId("group:" + id);
                row.setName(groupKey == null
                        ? messageBundle.getMessage(grouping == ReportGrouping.BY_GROUP
                                ? "grouping.noGroup" : "grouping.noDomain")
                        : metadataTools.getInstanceName(groupKey));
                return row;
            });
            counts.merge(header, 1, Integer::sum);
            reportRows.add(toReportRow(userReport, header));
        }
        headers.values().forEach(header ->
                header.setName(header.getName() + " (" + counts.get(header) + ")"));

        List<ReportListRow> rows = new ArrayList<>(headers.values());
        rows.addAll(reportRows);
        groupedRowsDc.setItems(rows);
        groupedReportsDataGrid.expand(headers.values());
    }

    private ReportListRow toReportRow(UserReport userReport, ReportListRow header) {
        Report report = userReport.getReport();
        ReportListRow row = dataManager.create(ReportListRow.class);
        row.setId("report:" + userReport.getId());
        row.setParent(header);
        row.setUserReport(userReport);
        row.setName(report.getName());
        row.setCode(report.getCode());
        row.setOwner(userReport.getSubdivision() == null
                ? null : metadataTools.getInstanceName(userReport.getSubdivision()));
        row.setReportGroup(report.getGroup() == null ? null : metadataTools.getInstanceName(report.getGroup()));
        row.setDomain(userReport.getDomain() == null ? null : userReport.getDomain().getInstanceName());
        return row;
    }

Mavjud initFilterListeners()ni quyidagicha yangilang. reloadReports() ichidagi resettingFilters tekshiruvi filtrlarni umumiy tozalashda faqat bitta yuklashni saqlaydi.

    private void initFilterListeners() {
        nameFilterField.addValueChangeListener(e -> reloadReports());
        codeFilterField.addValueChangeListener(e -> reloadReports());
        // Любой из двух фильтров переводит список в «Все» и блокирует select целиком.
        groupFilterField.addValueChangeListener(e -> onGroupingFilterChanged());

3.7 Load delegate: guruhlangan so'rov

@Install(to = "userReportsDl", target = Target.DATA_LOADER) metodida, buildFilterQuery()dan keyin va oddiy Sortdan oldin:

        if (isGrouped()) {
            // Сортировка по группе задаётся в самом запросе: левые соединения оставляют в списке
            // отчёты без группы или домена (они идут последними), а сортировка колонок в дереве
            // отключена. Так одна группа не разбрасывается по разным страницам.
            String query = groupingField.getValue() == ReportGrouping.BY_GROUP
                    ? "select e from UserReport e left join e.report r left join r.group g"
                    + filterQuery.where() + " order by g.title, r.name"
                    : "select e from UserReport e left join e.report r left join e.domain d"
                    + filterQuery.where() + " order by d.shortName, d.code, r.name";
            return dataManager.load(UserReport.class)
                    .query(query)
                    .condition(headerFilterCondition(loadContext.getQuery()))
                    .parameters(filterQuery.parameters())
                    .fetchPlan(loadContext.getFetchPlan())
                    .firstResult(loadContext.getQuery().getFirstResult())
                    .maxResults(loadContext.getQuery().getMaxResults())
                    .list();
        }
Bu yerda .sort(...) ishlatilmaydi. Tartib so'rovning o'zidagi order by bilan beriladi, chunki left join guruhi/domeni yo'q hisobotlarni ham ro'yxatda qoldiradi. Filtr shartlari (e.report..., e.domain) e aliasiga bog'langan, shuning uchun qo'shimcha join'lar ularni buzmaydi. Sanash (totalCountDelegate) o'zgarmaydi.

Eslatma: setValue(BY_GROUP) listener qo'shilishidan oldin chaqiriladi, shuning uchun listener ishlamaydi. Daraxtni boshidanoq ko'rsatish uchun applyGroupingMode() alohida chaqiriladi; birinchi yuklash esa isGrouped() orqali allaqachon guruh bo'yicha saralangan so'rovni ishlatadi.

6Boshqa tizimga moslash

  • Entity nomlari boshqacha bo'lsa: so'rovdagi UserReport, e.report, r.group, e.domain, g.title, d.shortName va rebuildGroupedRowsdagi getGroup() / getDomain() chaqiruvlarini moslang.
  • Yangi guruhlash turi qo'shish (masalan, «По владельцу»): enum'ga qiymat qo'shing, so'rovga left join + order by qo'shing va groupKey tanlovini kengaytiring. Bitta tarjima kaliti yetarli.
  • Jmix bo'lmagan tizim (masalan, React + REST): g'oya o'zgarmaydi. Backend sahifani ORDER BY group_name NULLS LAST, name bilan qaytaradi. Frontend sahifa ichida qatorlarni guruh bo'yicha bo'ladi va sarlavha qatorlarini qo'shadi. Jami son (total count) faqat hisobotlarni sanaydi.
  • Guruhlar standart yopiq bo'lsin desangiz: groupedReportsDataGrid.expand(...) qatorini olib tashlang.

7Tekshirish

  1. ./gradlew compileJava
  2. «Отчеты» sahifasini oching. Pagination oldida select borligini, standart qiymat «По группам» ekanini va ro'yxat darhol daraxt bo'lib chiqishini tekshiring.
  3. Daraxtda sarlavhalar soni bilan chiqadi, guruhlar alifbo tartibida, guruhsizlar oxirida.
  4. Hisobot qatorini tanlab «Выполнить» / «Описание» / «Доступы»ni bosing: tanlangan hisobot uchun ishlashi kerak. Sarlavha tanlansa, tugmalar tanlov yo'qligini bildiradi.
  5. Filtrlar (nom, kod, domen) va sahifalash guruhlangan rejimda ham ishlashini tekshiring.
  6. «По доменам»ni tanlang: hisobotlar domen sarlavhalari ostida chiqadi.
  7. «Все»ni tanlang: oddiy jadval va ustun bo'yicha saralash qaytadi.
  8. «По группам» va «По доменам» rejimlarining har birida alohida guruh, so‘ng alohida domen filtrini tanlab tekshiring: har safar select «Все»ga o‘tib, butunlay bloklanishi va tekis jadval chiqishi kerak.
  9. Ikkala filtrni tanlang, keyin bittasini tozalang: select «Все» qiymatida bloklanganicha qolishi kerak.
  10. Ikkala filtrni bittadan yoki umumiy tozalash tugmasi orqali tozalang: select qayta ochiladi, qiymat «Все» bo‘lib qoladi. Endi «По группам» va «По доменам»ni tanlash mumkin.
  11. Faqat nom, kod yoki srez filtrini o‘zgartiring: guruhlash selecti ochiq qolishi kerak.
